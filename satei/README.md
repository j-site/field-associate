# 不動産かんたん査定

一般の方が所有不動産の売却査定を申し込み、その情報を提携する不動産会社が購入できるサイト（一括査定型）。
静的ファイル（GitHub Pages など）＋ Supabase で動きます。

| ページ | 対象 | 内容 |
|---|---|---|
| `index.html` | 一般の方 | 査定の申込み（3ステップ・同意つき） |
| `partner.html` | 不動産会社 | 登録・審査待ち・査定依頼の購入・購入履歴・CSV書き出し |
| `admin.html` | 運営 | 不動産会社の審査、クレジット付与、依頼の管理・取り下げ、設定 |
| `partners.html` | 一般の方 | 提携不動産会社の一覧（提供先の明示） |
| `privacy.html` / `terms.html` | — | プライバシーポリシー・利用規約（**草案**） |

## しくみ

1. 一般の方が物件と連絡先を入力し、提携不動産会社（最大3社）への提供に同意して送信
2. 不動産会社は登録後、運営が宅建業の免許番号を確認して承認
3. 運営がクレジットを付与（入金は請求書払いなど、当面は手動）
4. 不動産会社は、購入前は**市区町村・面積の幅・築年代だけ**のプレビューを見て、クレジットで購入
5. 購入した会社にだけ、氏名・電話・メール・町名・番地が開示される
6. 1件の依頼は最大3社まで。上限に達すると自動で受付終了

## データの守り方

- テーブルには誰も直接触れない（RLS有効・権限なし）。すべて `schema.sql` の関数経由で、関数の中で権限を判定する
- 連絡先は物件情報と別テーブルで管理し、購入した会社にしか返さない
- 購入前のプレビューでは、町名・番地・正確な面積・築年を出さない（組み合わせると家が特定できるため）
- 同時に複数社が最後の1枠を買っても、成立するのは1社だけ（行ロック）
- 購入履歴が、個人情報保護法の **第三者提供の記録**（いつ・どの会社に・誰の情報を）を兼ねる
- 依頼ごとに、どの版の同意文に同意したかを記録する
- 取り下げの申し出があれば、連絡先を削除し、購入済みの会社からも見えなくする（提供記録は残す）

## セットアップ

1. [Supabase](https://supabase.com) でプロジェクトを作成
2. SQL Editor で `schema.sql` を実行
3. Authentication の設定で、メール＋パスワードでの登録を有効にする
4. `config.js` に Project URL と anon キー、運営者情報を記入
5. 運営者のアカウントを `partner.html` か `admin.html` から作成し、SQL Editor で権限を付与

   ```sql
   insert into public.admins (user_id)
   select id from auth.users where email = 'あなたのメールアドレス';
   ```

6. `admin.html` で、1件あたりのクレジット・最大社数・受付期間を設定

## テスト

Supabase と同じロール構成を再現した PostgreSQL で、権限と業務ルールを検証しています。

```bash
cd test && npm install
# PostgreSQL を起動したうえで
PGHOST=/tmp PGPORT=54329 PGUSER=postgres node --test sql.test.js   # DBの権限・ルール（39件）
PGHOST=/tmp PGPORT=54329 PGUSER=postgres node --test e2e.test.mjs  # ブラウザでの通し確認
```

- `sql.test.js`：匿名・未承認・他社から連絡先が見えないこと、二重購入・上限超過・クレジット不足・エリア外・期限切れの拒否、同時購入、取り下げ など
- `e2e.test.mjs`：本物のブラウザと supabase-js で「申込み → 業者登録 → 審査 → 購入 → 連絡先の開示 → 提供記録」までを通しで確認

## 公開前に必ずやること

- **プライバシーポリシーと利用規約を弁護士に確認してもらう**（現在は草案）
  - 特に、同意の取り方（提供先をどこまで具体的に示すか）と、提供記録の保存期間
- **料金は「1件ごとの利用料」にする**。成約に応じた報酬にすると、宅地建物取引業法上の媒介とみなされるおそれがある。運営は交渉・契約に関与しない
- 提携する不動産会社とは、利用料・クレジットの購入方法・返金の可否・禁止事項（情報の転売、しつこい勧誘）を契約書で取り決める
- 迷惑な送信が増えたら、Cloudflare Turnstile などのボット対策を追加する
