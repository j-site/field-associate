# propfinder

不動産賃貸業のための、物件の自動スクリーニング・収益計算エンジン。

新着物件を自動で拾い、**買っていい物件かどうかを数字で判定する**ところまでを自動化します。
賃貸として保有する場合と、販売用に仕入れる場合の両方を別々の基準で評価します。

## できること

| | 内容 |
|---|---|
| **収益計算** | 表面利回り・実質利回り（NOI）・DSCR・返済比率・税引後CF・自己資金回収期間 |
| **融資シミュレーション** | 元利均等返済、残存耐用年数による融資期間の制限、金利感応度 |
| **税務** | 中古資産の耐用年数（簡便法）、減価償却、購入諸費用、固都税、譲渡所得税 |
| **評価** | 積算価格（土地＋建物の原価）、収益還元価格、売出価格との乖離 |
| **出口** | 保有期間後の売却価格想定、残債、譲渡税、売却手取り、IRR |
| **選別** | 足切り条件＋4軸の重み付けスコアで自動ランキング |
| **取込** | 新着物件メールの自動解析、CSV、JSON |
| **相場検証** | 国交省「不動産情報ライブラリ」APIで実際の取引価格と突き合わせ |

## 使い方

```bash
cd propfinder

# 物件リストを一括スクリーニング（基準を満たすものだけ表示）
node cli.js screen data/sample.json

# 自分の投資基準を適用し、結果をCSVに出す
node cli.js screen data/sample.json --config config/criteria.json --csv result.csv

# 落ちた物件も理由付きで見る
node cli.js screen data/sample.json --all

# 1件を詳細分析
node cli.js analyze data/sample.json

# 新着物件メールをテキストで保存しておき、そのまま判定まで通す
node cli.js inbox mails.txt

# 抽出結果だけ確認（JSON）
node cli.js parse mails.txt
```

設定は `config/criteria.example.json` をコピーして使います。

## 物件データの形式

```json
{
  "name": "船橋RC一棟",
  "address": "千葉県船橋市本町",
  "price": 59800000,
  "annualRent": 6480000,
  "structure": "RC",
  "ageYears": 28,
  "landArea": 210.55,
  "buildingArea": 380.2,
  "rosenka": 135000
}
```

必須は `price` / `annualRent` / `structure` / `ageYears` の4つ。
`structure` は `RC` `SRC` `HEAVY_STEEL` `LIGHT_STEEL` `WOOD` など。

`rosenka`（相続税路線価・円/㎡）があると積算評価まで出せます。**無い場合は積算を
「0円」ではなく「判定不可」として扱い**、その軸を除いてスコアを再配分します。
情報が無いだけの物件を悪い物件として切り捨てないためです。

## メール取込について

楽待・健美家などのサイトを直接スクレイピングすることは利用規約違反・アカウント停止の
リスクがあるため、**ご自身が受信した新着メールを解析する方式**にしています。

`inbox` コマンドはテキストを空行で区切って複数件として扱います。Claude の Gmail 連携と
定期実行（Routine）を組み合わせれば、「新着メールを読む → 判定 → 結果を通知」までを
毎朝自動で回せます。

抽出できなかった項目は推測で埋めず `missing` として報告し、必須項目が欠けている物件は
スキップします。誤った数字で投資判断をしないためです。

## 国交省APIの利用

```bash
export REINFOLIB_API_KEY="取得したキー"
```

[不動産情報ライブラリ](https://www.reinfolib.mlit.go.jp/) で無料のAPIキーを申請できます。
取得できるのは成約価格（実際に取引された価格）で、売出価格が相場に対して割安か割高かの
裏取りに使います。取引事例が5件未満のエリアでは無理に判定せず `unknown` を返します。

## 前提と限界

- **税率・軽減措置は改正されます。** 既定値は概算用の目安で、`config` から上書きできる
  ようにしてあります。実際の取得前には必ず税理士・金融機関に確認してください。
- 積算価格の再調達価格は金融機関ごとに評価水準が異なります。取引行の水準に合わせて
  `rates.replacementCost` を調整してください。
- 譲渡所得の長期・短期は「譲渡した年の1月1日時点」で判定します。安全側に倒して
  既定では6年以上の保有を長期扱いにしています。
- 保有期間中の実効税率（`incomeTaxRate`）は、個人か法人か・他の所得がいくらあるかで
  大きく変わります。既定の33%はあくまで仮置きです。
- 空室率・修繕費は物件ごとの実態差が大きいため、レントロールが手に入る物件では
  実績値で上書きしてください。
